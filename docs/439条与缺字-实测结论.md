### 2.2 为什么不能直接「补」

1. `glyphs.dat` 是**升序 u32 码位表**，槽号 = 表内序号（旧 handler 的 `U0=group*64/4096`、`U1=(slot+1)*66/4096` 依赖它）。插入 19 个字会**把后面所有槽位整体移位** → 必须整张图集重排 = 重做 4096²/64 列/66 行距图集。
2. 项目现有图集生成器（`gen_atlas_4096.py` / `gen_atlas_final.py` / `gen_atlas_v2.py`）全部是 `CELL, COLS, SIZE = 32, 128, 4096`，与现行 64 列 / 64×66 格 / 18 起点**不符**，直接跑会毁图集。没有匹配的生成器可用。
3. 只往 `char_table.dat` 加码位而不加字形 → 该字位是空格子，显示为空白，等于没补。
4. 渲染已交给 `GTA4.CHS.fix.asi`，我们自研 `gta4cn.asi` 的图集/字表**已不再被消费**；要真正让这 19 字显示，得改 fix.asi 自带的 `fonts.wtd` 图集（渲染工程，与「冻结渲染线」冲突）。

### 2.3 现行处置

- **不擅自换字**（用户口径「不改译文」）。这 21 条译文全部保留原字，登记在案。
- 缺口登记为本阶段唯一挂起项，等最终总览时由用户拍板二选一：
  - **A 重做一张 64 列图集**，把这 19 字 + 全角空格补进去，替换 fix.asi 资源目录的 `fonts.wtd` + `char_table.dat`（需先写对 64 列生成器，工作量中等、有渲染风险）；
  - **B 用同类字替换这 21 条译文的 19 个缺字**（如 璀璨→辉煌、捋→理、瘆→渗、山芋→热山货、挑三拣四→挑挑拣拣、抖擞→百倍、抡→挥、钾→盐分、啵→啾、胖墩→胖小子、虱→虫、撬→掏、厩→马房、颚→牙床、姘→情妇、撵→轰、粝→糙），零渲染风险，但会轻微损失原字风味。
- 拉丁重音字符（é/á/ç/è/à/ú/ñ/ü/É/È）属外文名用字，两种图集都缺，同样归入拍板。
