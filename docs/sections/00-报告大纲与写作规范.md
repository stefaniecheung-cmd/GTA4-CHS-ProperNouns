# GTA4.CHS-技术路线解构 · 报告大纲与写作规范

> 本文件是最终报告 `gta4-chs\docs\GTA4.CHS-技术路线解构.md` 的结构基线与文风基线。
> 四份分节材料（01~04）是素材，**最终报告必须是自洽完整的一篇**，不能写成"详见第 N 节文件"。

## 1. 目标读者与用途

读者是本项目的实现方（正在从零写 `z_gta4cn.asi`，P1 骨架已完成、尚未挂任何 hook 的人）。
这份报告的唯一用途：**决定新方案在哪一层接管、用哪种定位手段、避开哪些坑**。不是测评第三方补丁好不好用，也不是教程。

因此每一节都必须落到"所以我们该怎么做"，只描述"它做了什么"而不给取舍的段落一律删掉。

## 3. 写作规范（硬约束）

1. **语言**：中文。技术名词首次出现给"中文（English）"，之后统一用其一，全文一致。
2. **证据标注**：每段结论后紧跟证据，格式 `【实测】文件偏移 0x0012A340 / RVA 0x008C5DF0` 或 `【推断】依据：…`。**禁止**把推断写成实测。
3. **数字**：地址一律 `0x` 前缀、大写十六进制；字节串用反引号包裹的 hex（`E9 3A 12 00 00`）；大小带单位。
4. **表格优先**：凡是"多处 / 多值 / 多文件"的对比，用表格，不用流水句。
5. **未知项**：写"未确定 + 卡在哪 + 还缺什么证据"，绝不留空、绝不编造。
6. **禁止**：编号式废话（"首先/其次/最后"堆叠）、空泛评价（"非常强大/十分巧妙"）、把工具输出原样粘贴超过 20 行（超过就摘要 + 指向附录）。
7. **篇幅**：正文 800~1400 行（约 45~70 KB）为宜；宁可在某节写深，也不要四节都写浅。素材合计约 105 KB，不要等比搬运：压掉重复的证据表，只保留能复核的关键行。
8. **不出现**：我方内部流程编号（P0/P1 可保留，因为本机记录已在用）、对第三方补丁作者的评价、任何"建议用户购买/安装该补丁"的表述。

## 5. 第 8 节必须正面回答的三个问题

1. 用 GXTStudio 打开并保存我们那三份 `chinese.gxt`，结构会不会被改坏（CRC、表偏移、内联表名）？
2. 那 26,713 条"中文与英文逐字节相同"的未译条目，能不能靠它的 AI 翻译 + 导出分表跑批量，跑完再导回去？
3. 中文字形不够时，它的 DAT 字库编辑能不能顶上，还是必须我们自己在绘制层做？

三条都要给出"能 / 不能 / 有条件下能"，并说清条件。
