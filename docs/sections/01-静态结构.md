## 3. 硬编码目标地址与绝对寻址

### 3.1 落在 GTAIV.exe 映像范围（`0x00400000`–`0x01400000`）的 32 位常量

对 `.text` 全量反汇编（36,147 条指令），枚举立即数与绝对内存寻址（`mov eax,[imm32]` / `mov [imm32],imm` 一类），结果：

- **指向 exe 映像范围的有效绝对地址：0 条。**
- 初筛曾出现 31 条落在 `0x01000193` 附近的"命中"，逐条核对均为 `imul reg, reg, 0x1000193` 的乘法立即数（常数 `0x1000193`），**不是地址引用**，已排除。
- 全文件按 4 字节对齐扫描 `0x00400000–0x01400000` 的结果为未对齐噪声（6,319 个误报，含 PE 头、代码字节、`.reloc` 项），无一被代码以 `mov/lea/push` 绝对寻址引用。

**结论：参照物不使用硬编码 exe RVA。** 目标定位完全依赖运行时特征码扫描（§4），补丁地址在扫描命中后于运行时计算得到。

## 4. 特征码 / 扫描方式

### 4.1 特征码存储形态

`.rdata` 内保存 61 条去重后的 **ASCII hex 指令序列**（空格分隔的两位十六进制，最小 4 字节、最大 19 字节，中位 6 字节），每条由对应注册 lambda 用 `push <串VA>` 推入匹配器。

- **通配符**：这 61 条中**没有 `?`/`??` 通配位**（解析后 wild=0）。运行时对候选字节做逐字节精确比较；立即数 / 相对跳转偏移在编译特征时已被固化为具体字节（见 §4.3 示例，短特征命中数很高，说明定位主要靠更长的上下文特征兜底）。
- 另有两处 7 字节"参考前缀"存在补丁记录区（`0x269AC`、`0x269B4`，见 §6.3）。

### 4.2 扫描引擎（静态还原）

扫描 / 落补丁相关函数与虚表分发（对象方法经 `mov eax,[ecx+off]; call eax` 调用）：

| asi VA | 角色 | 证据（反汇编要点） |
|---|---|---|
| `0x10008620` | 目标镜像 / 节定位 | `mov ecx,0x10037A48; call 0x1000C630` 取模块基址；读 PE 头 `[edi+0x3C]`（e_lfanew）→ 节表；按步长 `0x28` 遍历节，比对节名魔数 `.tex`（`cmp dword ptr [esi],0x7865742e`、`cmp byte [esi+4],0x74`）定位目标 `.text` 节 |
| `0x10008650`–`0x100086CB` | 节内候选遍历 | 以 `0x28` 为记录步长枚举；候选前缀 7 字节与参考字节比对（`cmp [ecx], [ebx]`、`movzx eax,word [ecx+4]; cmp ax,[ebx+4]`、`movzx eax,byte [ecx+6]; cmp al,[ebx+6]`），计数命中 `edx`，记录首个匹配 `esi` |
| `0x100086DE`–`0x10008701` | 二次校验 | `cmp byte [eax],0x14` 标志位；连续 9 字节 `0xCC` 填充校验（`cmp byte [esi+eax],0xCC; inc eax; cmp eax,9; jb …`） |

| `0x10006AD0 / 0x10006C10 / 0x10006B40 …` | 匹配器 / 闭包调度 | vtable 槽位调用：`[ecx+0x0C]`、`[ecx+0x10]`、`[ecx+0x30]`、`[ecx+0x38]`、`[ecx+0x3C]`、`[ecx+0x44]`、`[ecx+0x48]`、`[ecx+0x54]` |

## 5. 版本校验与兜底行为

### 5.1 是否比较文件大小 / PE 版本资源 / SHA1

- **文件大小**：asi 内未编码 exe 期望大小 `17,425,752`（双字扫描 `0x109E558` 计数 0）；导入表无 `GetFileSize`。
- **PE 版本资源**：无 `GetFileVersionInfo` / `VerQueryValue` 导入；asi 自身 `.rsrc` 仅 manifest，未读取 exe 版本资源。
- **SHA1 / 哈希**：无 `WinVerifyTrust`、无证书校验 API；除 json ABI 哈希串外无游戏侧指纹哈希。
- **版本串**：`1.2.0.59 sub_91EE50`（`0x269E0`）是**人工标注性质的记录项**，未被任何 `push/mov/lea` 指令直接引用，也未看到与运行时获取的版本字符串做 `strcmp` 的回路（静态判定为"未参与运行时校验"；不排除经数据结构间接读取，但静态证据不足，标 **未确定**）。

### 5.2 补丁记录区（`0x269C0`，可复算双字）

### 5.3 不匹配时的兜底行为

扫描 / 校验任一环节失败，控制流跳转到 `0x100087B2`：

```
0x100087B2  5F                pop edi
0x100087B3  5E                pop esi
0x100087B4  5D                pop ebp
0x100087B5  5B                pop ebx
0x100087B6  83 C4 1C          add esp, 0x1C
0x100087B9  C3                ret
```

**兜底结论：直接返回（静默跳过该补丁）。** 未发现日志写入、弹窗、异常抛出或降级改写；特征找不到 / 保护失败 / 校验不通过都沿上述出口退出对应注册函数。补丁写入后若 `VirtualProtect` 返回 0（`test eax,eax; setne al; je 0x10008763`），同样跳过回填，不报错。

## 7. 注入时机与加载器依赖

### 7.1 入口 / 初始化链（静态还原）

| 环节 | 地址 / 证据 |
|---|---|
| PE 入口点 | VA `0x1001DDB8`，标准 `DllMain(HINSTANCE, DWORD reason, LPVOID)`：`cmp [ebp+0xC],1; jne …; call 0x1001E692`（仅 reason=1 = `DLL_PROCESS_ATTACH` 时调用 `0x1001E692`），随后 `call 0x1001DC7F`（CRT wrapper） |
| CRT 包装 | `0x1001DC7F` → `0x1001DD8D`：经全局指针 `0x1002CBC0` 调用用户初始化；`0x1001DA6B` 按 reason 分派 ATTACH/DETACH/THREAD |
| ATTACH 回调 | `0x1001E692`：CRT 初始化状态检查后 `call 0x1001E645`（`_initterm` 类静态构造遍历），登记 `.CRT$XCU` 构造器（`.rdata` 指针表 `0x100271FC` 起：`0x1001EBD0 / 0x1001F030 / 0x1001F180 / 0x100208C0`…） |
| 业务注册 | 初始化包装 `0x10005F40`：`cmp [esp+8],1; jne 0x10005F5B; call 0x1000C700`（ATTACH 时执行 `gta_game` 等补丁注册）；`0x1000C700` 内依次调用 `0x10007650 / 0x10007D50 / 0x100083F0 / 0x10008B70 / 0x100096C0` 等分类注册器 |
| TLS 回调 | TLS 目录 `0x2D8C0`，回调表仅一项 `0x1001D401`（CRT TLS 初始化，非业务补丁线程） |

**时机判定：补丁初始化发生在 DLL 加载的 loader lock 内（DllMain / CRT 静态构造路径），未另起工作线程。** 依据：
- 导入表**无 `CreateThread` / `CreateRemoteThread`**；
- 无 `LoadLibraryA/W`、无延迟线程初始化；
- 业务注册由 ATTACH 回调同步调用链完成；TLS 回调仅 CRT 件。

### 7.2 加载器 / 前置依赖

- **ASI 加载器**：文件扩展名 `.asi`、无导出表、靠 DllMain 入口被注入——**依赖 ASI 加载器约定**（由加载器把 asi 放入游戏进程并调用其 DllMain）；asi 自身不实现自加载。
- **FusionFix**：二进制内未出现 `FusionFix` / `fusionfix` 字符串（计数 0），导入表也无其相关导出；静态侧**未发现对 FusionFix 的硬依赖**。是否在运行时经 `GetProcAddress` 探测其他 ASI/Fix 插件，静态证据不足（`GetProcAddress` 已导入，但未见指向外部插件名的字符串），标 **未确定**。
- **运行库**：静态链接 msvcrt 与 C++ 异常/RTTI，依赖 VC++ CRT 静态初始化；nlohmann-json 3.12.0 静态编译进二进制。
- **显示/图形依赖**：未导入任何 GDI / Direct3D 函数；字体与文本替换走内存补丁 + 外置数据表，不挂钩 D3D 渲染接口（静态判定）。

## 静态侧关键结论

1. **未加壳、标准 MSVC x86 DLL**：Machine `0x14C`，ImageBase `0x10000000`，5 个标准节，`.text` 熵 6.557；无导出表；资源段仅一份 `asInvoker` manifest，**不内嵌 GXT / 字体 / 文本块**。
2. **导入面很窄**：仅 KERNEL32（42）+ msvcrt（59）；**无** `VirtualAlloc`、`WriteProcessMemory`、`CreateThread`、`LoadLibrary`、Win32 文件创建、GDI/D3D。文件 IO 走 msvcrt `fopen/_wfsopen/fread`。
3. **零硬编码 exe 地址**：`.text` 内无任何指向 `0x00400000–0x01400000` 的有效绝对寻址；31 条初筛命中均为 `imul` 常数 `0x1000193` 误报。目标完全靠运行时特征扫描定位。
4. **特征码为 61 条 ASCII hex 指令序列（无通配位）**，4–19 字节、中位 6 字节；在 exe `.text` 复扫 33 条唯一命中、其余为多命中短特征；扫描引擎按 PE 节表定位 `.text`，以 `0x28` 步长遍历、7 字节前缀 + `0x14` 标志 + 9 字节 `0xCC` 校验，写前 `VirtualProtect(0x40)` 备份原字节、写 `0xE9` JMP 跳板后恢复保护。
5. **与我方 4 个文本函数入口零重合**：61 条特征无一落在 `0x4C5CC0 / 0x4C5D70 / 0x4C5DF0 / 0x4C5E80 / 0x4C6780` ±0x40；asi 内也无 `CHINESE.GXT`、`common:/text`、`%s/%s`、`TABL/TKEY/TDAT` 或任一语言名。**它不走改写 GXT 文件名 / 文本目录 / 路径拼接 / GXT 解析器这条链。**
6. **无版本大小 / 资源 / 哈希校验**：未编码 exe 大小，无版本资源与证书校验 API；`1.2.0.59 sub_91EE50` 是未被直接引用的标注串。校验/扫描失败时**静默返回**（`0x100087B2` 出口），不写日志、不弹窗、不降级。
7. **初始化在 loader lock 内同步完成**：补丁注册走 DllMain ATTACH → CRT 静态构造 → 分类 lambda（`gta_game/font/menu/phone/save/html/mail_reply/whm/benchmark`），未起工作线程；依赖 ASI 加载器约定，静态未见 FusionFix 硬依赖。
8. **外置资源三件套**：`char_table.dat`（字符表）、`whm_table.dat`（字形表）、`custom_translations.json`（JSON 自定义翻译），键名 `font_chs`；文本/字形数据外置，二进制内不含对应内容。
