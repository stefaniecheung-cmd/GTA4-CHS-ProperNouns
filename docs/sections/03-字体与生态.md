> 分析对象：`C:\Game\Grand Theft Auto IV\plugins\GTA4.CHS.asi`（232,960 字节）。
> 方法：PE 静态解析（pefile 2024.8.26）＋ capstone 5.0.7 反汇编 32 位 `.text`，外挂数据表二进制解剖，目录/文件清单实测。全程只读：未改游戏目录任何文件，未部署、未运行该 asi；临时脚本与中间产物在 `C:\Game\_tools\chs_re\`。

## 2. 字体与字形（主项）

### 2.1 它读哪些文件、写不写盘

**结论 2.1**
- `【实测】` asi 本身**不读取、也不生成** `FONTS.DAT` / `FONTS_R.DAT` / `fonts_j.dat` / 任何 `.ttf` / `.otf` / `.gfx` / `.wtd` / `.gxt`；它只读 `plugins\GTA4.CHS\` 下那三份数据文件。
- `【实测】` 导入表与模式串均为只读侧；`【推断】` 运行期不向磁盘写任何文件（无写 API、无写路径字符串、无映射视图调用）。字体图集与文本字典的落地全部由外部安装包（见 3.5）在文件层完成，asi 只在内存里接管游戏代码。

### 2.2 是否自带字形图集（atlas）

| 排查项 | 结果（实测） |
|---|---|
| 位图/容器魔数 | `BM`(BMP)、`\x89PNG`、`DDS `、`RIFF`、`GFX`、`RSC` 均 **0 个有效命中**；`\x00\x00\x01\x00` 的 105 处命中为零填充/跳转立即数巧合，非 ICO 资源 |
| 近常量数据块 | 全段 4 KB 窗口扫描，0 个"零/255 占比 >90%"的 1bpp/8bpp 字模阵列 |
| 段熵 | `.text` ≈ 7.49、`.rdata` ≈ 5.75、`.data` ≈ 3.43；无大段等宽重复的字形栅格区 |
| `.rsrc` | 仅一条 asInvoker 的 UAC manifest XML，无版本信息、无图片资源 |

**结论 2.2**：`【实测】` asi 内部**未内嵌位图字模/图集**；字形来自外部部署的字库 wtd（见 2.3）。asi 体积 232,960 字节里的大段二进制是 `.rdata` 中的代码特征模式串与 RTTI/字符串，不是纹理。

### 2.4 `char_table.dat`：允许字符名单（实测解剖）

| 项 | 值 |
|---|---|

| 头 | u32 LE 计数 `0x0DFC` = **3,580** |
| 条目 | 3,580 个 u32 LE Unicode 码位，**已按升序排列**（实测 `sorted == True`） |
| 码位范围 | 最小 `U+2014`（—），最大 `U+FF65`（･） |

### 2.5 `whm_table.dat`：实测为**译文串池**，不是字宽表（纠偏）

| 项 | 值（实测） |
|---|---|
| 大小 | 780,676 字节 |
| 头 | u32 LE 计数 `0x150C` = **5,388** |
| 头部散列区 | 偏移 `0x0004` 起，按 8 字节成对：前 4 字节高熵散列值，后 4 字节递增索引（样例：`0x1F83C19A/0`、`0x7D231CA3/5`、`0x35B02476/22`、`0x6C0E6BAA/42` …）；散列区共 4 + 5,388 × 8 = 43,108 字节，结束于 `0xA864` |
| 串池区 | `0xA864` 起 737,568 字节；NUL 分隔出 5,382 段，其中 **5,349 段含 CJK 汉字**，平均 48.7 字符，最长 666 字符 |
| 串样例 | `男`、`文化评论员`、`三流白人男性`、`爱好: 写博客、写关于博客的博客…`、`卡瑟市`、`好累，已经产生幻觉了…`（短信/网页/博客类中文译文） |

- `【推断】` 条目结构为 `{散列 u32, 串池索引 u32}`，散列键是英文原文的某种编码；散列算法/密钥本次未还原（卡在头部 4 字节高熵值无法反推明文映射）。
- **纠偏**：文件名字面像 "width/height metrics"，但实测串池内容是中文译文而非逐字宽高；对应 RTTI 命名空间 `gta_whm`。字宽数据不在此文件（见 2.6）。
- 旁挂文件 `custom_translations.json+滤镜中文翻译`（3,123 字节，89 键）与已加载的 `custom_translations.json`（3,046 字节，86 键，UI 选项译名如 `SkipIntro→跳过开场`、`Bloom→泛光`）并存；`【实测】` asi 字符串只引用无加号的那份，加号文件是否被读取未在代码中找到引用点。

### 2.6 字宽模型：全角等宽还是实测宽度

| 证据 | 结论 |
|---|---|
| `【实测】` asi 内无独立字宽表文件，无 `.ttf/.otf`，`.rdata/.data` 中未发现逐字宽度数组（u8/u16 宽度表解剖无对应结构） | 宽度不由 asi 自带数据表提供 |
| `【实测】` 排版/测量路径函数 `0x10006663` 引用一组浮点与整型单元常量（见 2.8），字符先经 `0x10005850` 判定是否在 `char_table` 名单内 | 中文走补丁后的测量路径，按名单成员身份分流 |
| `【推断】` CJK 按全角固定单元排版，拉丁/标点沿用游戏原版字宽；逐字字形度量来自外部 `fonts_chs.wtd` 字模与游戏原排版代码，asi 在测量 hook 里做单元换算与缩放 | 依据：名单成员制 + 单元常量 32/64/66，未见逐字实测宽度读取 |

未确定：wtd 内每个字形的步进（advance）字段结构本次未解剖，无法逐字核对全角/半角；需要在能解包 wtd 的工具里复核。

### 2.7 缺字兜底

`【实测】` 成员判定 `0x10005850` 二分未命中时，落到 `0x100058B6` 分支，**改查回退码位 `U+FF1F`（全角问号 `？`）**，而不是直接跳过或回退英文。

`【实测】` 标点白名单函数 `0x10006940` 逐条比较以下全角/中文标点，命中则按双字节（UTF-16 单元）放行：

| 码位 | 字符 | 码位 | 字符 |
|---|---|---|---|
| `0x3001` | 、 | `0xFF1A` | ： |
| `0x3002` | 。 | `0xFF1B` | ； |
| `0x300F` | 』 | `0xFF1F` | ？ |
| `0xFF01` | ！ | `0xFF5E` | ～ |
| `0xFF0C` | ， | `0x2026` | … |

`【推断】` 若连回退码 `U+FF1F` 都不在名单内，二分返回未命中索引；最终是画占位符还是保留原字符，取决于游戏绘制层分支，asi 内未发现画空方框的位图路径。未在本机真机观察过缺字现象，此分支行为待运行期复核。

## 5. 字体与生态关键结论

1. **asi 自身不碰字体文件、不写盘**：仅以只读 stdio（`"rb"`）读取 `char_table.dat` / `whm_table.dat` / `custom_translations.json`；导入表无任何写文件/内存映射 API，无 `.ttf/.otf/.gfx/.wtd/.gxt` 字符串（实测，2.1）。
2. **字形图集不在 asi 内**：无 BMP/PNG/DDS 魔数、无近常量字模块、段熵正常；中文字形来自外部三章 `fonts_chs.wtd`（实测，2.2、2.3）。
3. **`char_table.dat` 是 3,580 字升序 Unicode 名单**（头 u32 计数 + u32 码位数组），二分成员判定在 `0x10005850`；原汉化补丁名单为 3,517（实测，2.4）。
4. **`whm_table.dat` 是中文译文串池，不是字宽表**：5,388 条 `{散列, 索引}` 头 + 737,568 字节 NUL 分隔串池（5,349 段含汉字）；逐字宽度不由它提供（实测 + 纠偏，2.5）。
5. **缺字兜底为回退全角问号 `U+FF1F`**；另有 10 个中文/全角标点白名单在 `0x10006940` 双字节放行（实测，2.7）。
6. **字号/行距为硬编码常量、无配置项**：排版函数 `0x10006663` 内单元 31/32/64/66、缩放 0.06558/0.06712/0.9531；未见独立行距重调（实测 + 推断，2.8）。
7. **加载链是 UAL 9.7.4 字母序加载**；CHS 补丁走内存 sigpatch、不挂 D3D，与 DXVK/SISCO/雨滴/DLSS 等渲染层正交；真正同层冲突只在 FusionFix、ScriptHookDotNet 与未来本项目自己的文本 hook（实测 + 推断，3.1、3.4）。
8. **当前 `z_gta4cn.asi` 无 hook、无图形/文本导入，与 CHS 共存无行为冲突**；但后续挂 hook 后不能与 CHS 叠加启用——同一批游戏函数会被二次改写，新方案应走取代路线，回归前先移出 CHS（实测 + 推断，3.6）。
