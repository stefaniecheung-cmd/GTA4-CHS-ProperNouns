### hook 窗口收尾移交 → 主线接手（2026-11-08）

> 来源：`docs\P4-渲染hook-逆向落地方案.md`（48.9 KB，含地址总表/判据表/换算表/决策树）、`docs\P4-hook交接-代码侧.md`、`chs\logs\fontdbg.txt`（2026-11-08 20:32:15 那次失败运行的盘上取证）。

**结论翻盘：不是「没画」，是「宽度被压成竖条」**

- `bq`(0x91B850) = `vx`(0x90A360) = `sdN` = **1,738,124**，三者严格相等 → 每个到达 StubDraw 的字都完整走完 quad 生成与顶点写入，「整批丢弃」被排除。
- 8 个顶点样本 / 4 个字形（idx 3114/3574/1630/1918）：**Δx 全部 3.1186 px、Δy 全部 −16.998 px**；UV 侧 ΔU=ΔV=0.0078125=32/4096，`u_left=col*32/4096`，与 `idx=row*128+col` 严丝合缝 → 位置对、格位对，但**一个字只占 3 px 宽（1:5.45），肉眼等同消失**。
- `tex[0]=tex[1]=tex[3]=0x48274250` 非空、`tex[2]=0`；`hit=1,361,436` 与 `uvApplied` 逐字体加总严格相等 → 绑图与查表命中一一对应。

**三条候选判定**：①`A+0x2C` 特殊字符标志置 1 → **未排除**（标志检查 `0x921763` 早于 StubDraw 原点 `0x92176E`，被拦字不进 `sdN`；`lookN − sdN = 299,182`＝14.7% 正好是这个口子）；②绑错图 → **基本排除**（部署 wtd 的 SHA256 与已校验件逐字节相同，1,590,798 B）；③quad 塌陷 → **已确认（宽度轴）**。

**主因假说：宽度层从来没被接管。** 旧参考补丁 `GTA4.CHS.asi` 在宽度层有 6 个安装点（`0x79A0`/`0x79CD`、`0x7BD1`/`0x7BF8`、`0x7C30`/`0x7C60`），而自研补丁 `gta4cn.log` 只有 `probe 0 at 0x014FC7C0` —— 宽度函数 `0x91C7C0` 只挂了计数探针，一次都没接管。我们只改了「贴哪块图」，没改「这一步该走多宽」。两条互斥机理：**H2**（引擎对未登记码点给兜底 advance → 修法补宽度 hook）／**H1**（`font.cpp:140` 的 `xor esi,esi` 污染度量 → 修法取消置 0）。E3-a 静态判据可把 H1 出局：看 `call 0x91C7C0` 是否在 `0x92159E` 之前。

**三处必须改口径（旧笔记是错的）**

1. **`dl==0` 门在当前部署件里不存在**。扫 `.text` 找 `cmp dl,0`/`cmp cl,0` 全 0 命中；引擎侧唯一字体比较是 `0x92114C 80 3D C1 66 03 01 03`（`font==3` 早退），路径 B 条件是 `font==2`。那道门是更早一版 stub，在 ASI 自己代码里，「扫出 0 命中」是方法错不是证据缺失。
2. 度量常量：`+0x24C(40.0)` / `+0x250(4.0)` / `+0x254(39.5)`，U 除数在 `+0x248(512.0)`；**贴图槽 `+0x240` 与这些度量常量同处一个子结构**，这解释了为什么只改指针不改常量会出事。
3. `0.97266−0.96094` 实为 `48/4096` 而非 `32/4096`（正确 UV 仍是 32/4096）→ **UV 侧可以结案**。

**栈帧槽位表（2026-11-08 23:5x 按 `0x92176E..0x9217EA` 全段反汇编逐条校正，此表为准）**：
帧 `sub esp,0x30` + push esi/edi，A=sub esp 之后的 esp，hook 入口 esp=A−8（=E）。

| 槽 | 引擎读取点 | 语义 |
|---|---|---|
| **`A+0x24`（入口 `[esp+2Ch]`）** | `0x921786 movss xmm0,[esp+0x2c]`（esp=E） | **像素前移量 W** ← 汉字被压成 3.1186 px 的就是它 |
| **`A+0x28`（入口 `[esp+30h]`）** | `0x9217b7 movss xmm0,[esp+0x3c]`（esp=E−12） | **高度 H** → 决定 Y 跨度（实测 16.998 px） |
| `A+0x20`（入口 `[esp+28h]`） | `0x9217a6 addss xmm7,[esp+0x30]`（esp=E−8） | **UV 宽度（U_right 增量）**，恒 `4/512 = 0.0078125` → 写它 = no-op |
| `A+0x2C` | `0x921763 cmp byte [esp+0x34],0`（esp=A−0x10） | 特殊字符标志，非 0 → `jne 0x9217F2` 直接不画（`si==0xFD`/`0xFFFF` 置 1） |
| `A+0x34`/`0x38`/`0x40` | `0x921780`/`0x921790`/`0x92178c` | 调用方 x / y / 参数 |

block1 = `{ X, Y+H, X+W, Y }` → 四边形像素尺寸 = **W × H**。
ε 像素乘数实测：字宽槽 ≈1925、高度槽 ≈1080（比值 0.5610）→ 正方形需 `advance = H × 0.5610`。
**机理定论（REA 逆向）**：`FUN_10006120` 兜底分支的表达式里没有 `ch`，非 ASCII 全部拿同一常量 advance → **宽度层必须单独接管**。

### 关键设计决策（主窗口必须知道，否则会改错）

1. **不重排图集**。资源线的 4096²/128 列/格 32×32 直接可用；hook 2 是「按索引重算 UV」，不是「在引擎 UV 上加页偏移」。因为在引擎 16 列/格 32×40 的坐标系里加偏移必然错位。
2. **`si` 在 hook 1 里被置 0**，是为了避开 `cmp si,0xC0` 的基值切换和 `cmp si,di`（di=0xFD）的特判。真实格位走全局 `g_idx`。
3. **hook 2 只对 `dl==0`（font0）生效**。font1/font3 贴图仍是原版 1024²，不能按 4096 换算。
4. **`[esp+0x30]` 被改写成 32/4096**，因为 `0x9217A6 addss xmm7,[esp+0x30]` 用它算右边界。
5. 图集布局常量在 `font.cpp` 顶部：`kAtlas=4096 / kCols=128 / kCell=32`。改布局只改这三个。

### REA 逆向：旧汉化 hook 手法（2026-11-08 23:45 取证，已结案）

**结论：旧汉化不是手写偏移 hook，而是一套 C++ patch 框架 + 特征码扫描。**

- 源码结构（Ghidra 从 RTTI 恢复，非推测）：五个模块各有 `register_patches(batch_matching&)`
  - `gta_benchmark` 1 条 / **`gta_font` 14 条** / `gta_game` 18 条 / `gta_html` 7 条 / `gta_mail_reply` 9 条
  - 类型 `batch_matching` / `memory_pointer` / `std::vector<memory_pointer> const&`
- hook 手法：`VirtualProtect(PAGE_EXECUTE_READWRITE)` → 写 5 字节 `E9 rel32` → 立即还原 → 备份原跳转
  - `FUN_10007680`（164 B）安装器；`FUN_10006fd0`（320 B）取原跳转（E8/E9 解析、FF15/FF25 取指针）
- 安装点**只有 3 处**（不是 6 处）：`FUN_10007980` / `FUN_100079B0` / `FUN_10007B80`
  - 对应 handler `0x10006210`（测宽 892 B）/ `0x100061A0` / `0x10006A90`，len 均为 1
  - 后两个 handler 不是函数入口（落在函数间隙），是「从函数中间切入」的做法
- patch 描述表在 `.rdata` `0x10027638` 起，每项 28 B，共 62 项；字段 `+14` 即安装执行器
- **29 条特征码字符串全部躺盘**：`.rdata` `0x100276E0`–`0x10028448`，可直接复用
  - 第一条 `83 C0 E0 50 E8 ? ? ? ?` = `add eax,-0x20; push eax; call`，正是测宽里 `FUN_10006120(ch-0x20)` 那句

**宽度层定因（已闭环）**

- `FUN_10006120(ch)`：`FUN_10001d50((ch+0x20))` 为真走原始测宽；否则走兜底分支
- `FUN_10001d50` 只有 12 B：`return x < 0x100` —— 判的是 **ASCII 半角区，不是汉字**
- 兜底分支表达式里**没有字符码**，索引来自 `fontRec[0x28+f*0x48]` / `[0x29+f*0x48]`
- → 任何汉字拿到**同一个常量 advance**，与真机 `Δx ≡ 3.1186 px`（4 个不同字形）严格对应

**对自研的直接影响**

1. 宽度必须单独接管引擎侧测宽（`0x91C7C0`，路径 B 在 `0x921537` 调用），不是 ASI 内部逻辑
2. `gta_font` 需要 14 处干预，我们目前只覆盖 1–2 处 —— 宽度只是其中一环
3. 特征码直接抄，不用自己造
4. 汉字 advance 应按 `32 / 该字体 scale` 推导（图集 4096²/128 列/32 px），不能拍数字

**仍未查清**：`0x100061A0` / `0x10006A90` 两个 handler 语义、每个 lambda 捕获的 pattern、`batch_matching` 匹配实现。

> 完整取证见 `docs\REA-宽度层逆向-取证与结论.md`（含 29 条特征码全表）。
