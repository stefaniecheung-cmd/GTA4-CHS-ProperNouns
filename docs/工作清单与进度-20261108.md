## 三、字形线（P4-hook，已移交后台）

### 3.1 打通了、有硬证据的（5 项）

| 项 | 证据 |
|---|---|
| 链路定位 | `0x921140 → 0x921534 → 0x92159E(hook①) → 0x92176E(hook②) → 0x91B850 → 0x90A360 写顶点 → 0x923140 绑贴图 → 0x8D4340 提交` |
| 唯一通道 | `0x8D4340` 全游戏仅 2 个调用点（`0x923183`/`0x9231C2`），都在 `0x923140` 内 |
| 取字层 | 字符表 3,597 码点、3,584 条进表，离线抽样核对无误 |
| UV 顶点级 | `0x90A360` 入参 0.96094 / 0.02344 / 0.97266，差 `32/4096`，与 idx=379 在 128 列图集格位严格一致 |
| 根因定因 | 菜单文字 18,324 次**全走 font1**，而两处 hook 原本都有 `dl==0` 门——这是页签全 `!` 的根因 |

### 3.2 卡在哪（一句话）

> 把接管扩到 font1/font3、贴图指针重定向到 4096 图集后，**真机所有文字彻底消失（连 ASCII 都没了）**。静态证据解释不了：UV 对、指针统一、资源好，就算坐标系不匹配，ASCII 也该显示成随机汉字而不是空白。

三个候选原因：① `A+0x2C` 特殊字符标志被置 1 跳过绘制；② 批次绑到的不是以为那张图；③ quad 尺寸塌陷。

**已定的下一窗口起点**：先落一次「`0x923140` 绑定的贴图指针 + 顶点缓冲前 36 B」的 dump，回答「那张图到底是谁、quad 有多大」，再决定继续方案 A 还是转 C。**不要再动 `[esp+XX]` 偏移**（前两轮改错两次纯属浪费，那个写操作本身是 no-op）。
