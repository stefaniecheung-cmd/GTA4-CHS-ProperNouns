## 三、汉化质检还应该查什么（建议补充项）

你已提的四类（控制符、颜色码、占位符、双字节长度/编码）都已覆盖并有报告。下面按「已做 / 建议补做」分列。

2. 颜色码复位与串色风险——同上

8. 术语一致性（`术语表.md` 强制）——闸门 0 错 0 警

### 建议补做（我认为是漏项，按优先级）

| 优先级 | 检查项 | 为什么必须查 |
|---|---|---|
| **P0** | **非汉字字符的图集覆盖**：全角标点 `，。！？：；、`、破折号 `——`、省略号 `…`、书名号 `《》`、引号 `「」`、括号 `（）` 是否都在旧补丁那 3,580 个码点里 | 我此前只统计了 3,302 个**汉字**，没查标点符号。缺一个标点，游戏里就是空白方块——这正是「乱码错字」最隐蔽的来源 |
| **P0** | **控制符大小写与白名单**：原文存在 `~S~`/`~Y~`/`~B~` 大写形态（如 `~S~Take the van to the ~Y~lockup.`），我方译文是否与原文一致、有没有写旧补丁不认的 `~XXX~` | 旧补丁按字符串解析，大小写不一致可能整条不解析，界面上直接显示 `~S~` 原文 |
| P1 | **单条文本行数与字符上限**（按文本框分档：任务提示/对话气泡/字幕/菜单） | 比「宽度比值」更贴真实 UI，能抓「多一行被裁掉」 |
| P1 | **占位符语义搭配**：`~1~` 前的量词与数字是否成立（「~1~ 秒」不能变成「1 秒」「~1~ 秒钟」错位） | 数量对但语义错，玩家看到「你还有3秒」变「你还有 秒」 |
| P1 | **格式化残留**：`%s`、`%d`、`{0}`、`\\n`、`&amp;`、`<br />` 变体（`<BR>`、`<br>`） | 非 GXT 语法的标记会原样显示 |
| P2 | **全半角数字/字母混用**（`１` vs `1`、`Ａ` vs `A`） | 字体图集里全角数字可能不存在 |
| P2 | **引号体系统一**：全库 `“”` 与 `「」` 是否混用 | 影响观感一致性，也占宽度 |
| P2 | **重复 crc 多行同时生效**（覆盖表带 chapter 的行是否唯一生效） | 已做过碰撞审计，建议随每次重打包复跑 |
| P3 | **抽样语义校对**：按表类型分层抽 200 条，德法对照核「是否译反/译漏」 | 机械判据抓不到语义错误（本轮就抓到 `Anyway, she was maybe...` 只译成「是啊」） |
| P3 | **真机截图抽查**：菜单/任务提示/对话/字幕各一张，确认无方块、无截断 | 一切判据的最终验收 |
