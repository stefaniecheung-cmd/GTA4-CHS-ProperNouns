# 渲染与编码校验说明（三语对照 + 双字节风险）

> 目的：在译文最终序列化进 `zchs_*.gxt` 之前，用英/德/法官方文本当参照，把「会影响引擎渲染」的问题挑干净。
> 两个脚本都是独立闸门，可随时重跑，不依赖翻译进度。

## 一、覆盖范围：三章全部 102,129 条，一条不漏

两个检查器都不再按「是否含中文」过滤，而是遍历三章打包输入的全部行：

| 来源 | 条数 | 含义 |
|---|---|---|
| 我方 | 2,870 | crc 出现在 `zh_global.tsv` 或 `zh_*.tsv` 分片里，是我写的 |
| 上游 | 58,378 | 含中文但不在我方表里，来自上游语料 |
| 未译 | 40,881 | 仍是英文，待补译 |

报告的每一行都带 `来源` 列，问题可按来源分组统计。**无参照 0 条**（每行都在 `corpus_*.tsv` 里找到了英/德/法对照）。

## 三、① 三语控制符比对（`ctrl_threeway.py`）

以每条的英文原文为基准，同时取德法文本做旁证：

| 判据 | 含义 | 是否严重 |
|---|---|---|
| 控制符丢失 | 英文有、我们没有 | 严重 |
| 控制符多余 | 我们有、英文没有 | 分情况 |
| 强证据缺失 | 英文有、**德法都保留**、我们没有 | 严重（多半是真丢） |
| 顺序不符 | 集合相同、顺序不同 | 涉颜色/占位符才严重 |
| 颜色码差异 | 颜色集合既不等于英文、也不等于「德法一致」 | 严重 |
| 占位符不符 | `~a~`/`~1~`/`~e~`/`~d~` 个数与英文不等 | 严重 |

**已撤掉的判据**：`~s~` 复位数量。GTA IV 的颜色码是「下一个覆盖上一个」，不靠 `~s~` 复位，硬判会全是误报。
**已知的正常项**：`~s~` 收尾（官方译文也这么写）、`~n~` 断行（中文比英文长，需要换行）。

当前基线（全量 102,129 条）：命中 352 条 —— 上游 322 / 我方 30，其中**严重 38 条**。
40 条逐条看过：38 条是中文语序把时间/颜色码挪了位置（集合完全一致，渲染无影响），2 条是上游擅加颜色码，**已改掉**。

## 四、② 双字节与编码检查（`render_checks.py`）

中文是双字节，这几类问题只有中文才会出：

| 判据 | 说明 | 级别 |
|---|---|---|
| 单行超宽 | 按 `~n~` 切行，中文按 2 半角宽算，某行 > 英文同位置 1.25 倍 | 严重（会挤出对话框） |
| 整体偏长 | 整句宽 > 英文 1.35 倍 | 提示 |
| 整体偏短 | 只剩 2–3 字而英文有 4 词以上 | 严重（疑截断/漏译） |
| 译文为空 | 英文有内容、译文只剩控制符 | 严重 |
| 编码异常 | U+FFFD / BOM / 零宽 / NBSP / C1 控制字符 | 严重（会显示方块或吞字） |
| 半角标点 | 中文句子里夹 `. , ! ? : ;` | 严重（字形宽度不一致） |
| 引号括号失衡 | `「」`/`（）`/`《》` 数量不成对 | 严重 |
| 连续空格 / 首尾空格 | 排版噪声 | 提示 |

### 本轮修掉的（写入 `zh_global.tsv`，每条都带 `was` 说明）

| 规则 | 条数 | 说明 |
|---|---|---|
| R4 半角标点转全角 | 96 | 中文旁孤立的 `. , ! ? : ;` → 全角；**省略号 `...` 与连续标点不动** |
| R7 引号补正 | 74 + 7 | 只有左引号补右、只有孤立右引号删掉 |
| R6 清除 C1 控制字符 | 22 + 3 | `™` 被误存成 U+0099、另有 U+0094，游戏字体没有这些字形 |
| R2 去全角空格 | 21 | 上游用 `　` 做字间距，行宽直接撑爆 1.5 倍 |
| R3 颜色码对齐英文 | 2 | `70ECE254`、`00AD5CCD` 上游擅加 `~b~`/`~y~` |

**中途踩过的坑（已撤回重做）**：第一版把 `.` 一律转 `。`，把 881 处 `...` 拆成 `。..`。已整表撤回、改成「只看孤立标点」，重跑确认 1,810 处省略号完好，剩下 13 处 `...？` 是母本原有写法。

当前基线（全量 102,129 条）：命中 174 条，严重 66 条 —— 我方 15 / 上游 55 / 未译 0。编码异常与半角标点已清零；剩下的全是排版判断项（单行超宽 46、整体偏长 36、整体偏短 17、引号 2）。

## 闸门覆盖范围的两个漏洞（2026-11-08 已修）

### 漏洞一：闸门只跑 base 章

`qa_gate.py` 原先主程序只调用 `check("base")`，TLAD / TBoGT 的 `zh_*.tsv` 从未过闸。
之前所有「闸门 0 错 0 警」的结论只覆盖 base。已改成三章全跑。

### 漏洞二：覆盖表条目只被间接检查

覆盖表 `zh_global.tsv` 的 2,264 行里，只有与分片里同一个 crc 重合的部分才会进入闸门判定；
TBoGT 章根本没有分片文件（该章 199 条全部住在覆盖表），因此「检查 0 条」却显示通过。
已改成：覆盖表逐行独立检查（原文优先从 `corpus_<chapter>.tsv` 取，取不到再退回 `translate_queue.tsv`），
分片里与覆盖表重复的条目不再重复判定。现覆盖 2,016 条有中文的条目。

### 漏洞三（最严重）：crc 跨章碰撞被「全章」行串译

同一个 crc 在不同资料片里可以对应**完全不同的英文**。实测三章合计：
- 跨章共用同一 crc：1,112 个
- 其中英文不同的：449 个

覆盖表原先以「chapter 留空＝全章生效」处理，落在这 449 个里的有 24 条，
结果是一章的译文覆盖到另一章：

| 现象 | 条数 | 后果 |
|---|---|---|
| 一章是 `PLACEHOLDER`、另一章是正文 | 12 | 正文被替换成「占位符」，真实台词丢失 |
| 两章正文不同（如两封不同的垃圾邮件） | 4 | 串成另一章的文案 |
| 通用指令措辞不同（wanted level / cops） | 5 | 术语错配 |
| 模式名不同（Deathmatch / Team Deathmatch） | 3 | 模式名错配 |

已按章拆分：删 24 条「全章」行，写 50 条按章明文，并为每章重新翻译对应原文。
拆分后复查：落碰撞 crc 上的空白 chapter 行为 0。

拆分带来的连带修正：三语比对「我方」从 30 条降到 27 条；渲染检查严重项从 68 条降到 54 条
（`整体偏短` 17 → 5，主要是占位符错配被消掉）。

### 附带修掉的两处

- `qa_gate.py` 原文索引改为 (章节, crc) 二元组，否则同一个 crc 会取到别章的英文，判据全部失真。
- `Green`（LCPD 犯罪档案里的姓氏）补译为「格林」；`LOST AND DAMNED TEAM DEATHMATCH` 补译为「失落与诅咒 团队死斗」。
