## 六、已定口径（摘要，细节见对应文档）

- 官方模式名/队名/电台名/歌曲名/外文原名 **保留英文，只翻外围句子**。
- `PLACEHOLDER`/纯符号 → 「占位符」或原样保留。
- 下游对上游不一致的译法 **要统一纠正，不跟随上游瑕疵**。
- `Job` 语境为手机通讯录「接活」功能 → 全篇统一「差事」（含 `JOB:`→「差事：」）。
- 短词吃不准 → 查德法对照 → 仍不确定逐条发用户，过了才下一项。
- **德法对照不是绝对参照**：法文版 `62B99117` 独有真实内容 `Nouveau RV avec ECOWARRIOR`，英文/德文均为 `PLACHOLDER`，属各语种独立维护的键漂移。

## 七、风险与已知坑（勿重复踩）

1. `dinput8.dll` 是 ThirteenAG ASI Loader，**按文件名含 `.asi` 子串加载**，改名 `.asi.off` 不能禁用；可靠禁用只能移出目录。
2. 抓游戏画面必须窗口模式 + `PrintWindow(hwnd, hdc, 2)`；独占全屏抓不到、`cu.screenshot()` 无效。
3. `.bat` 必须纯 ASCII（中文注释会按 GBK 解析成乱码命令）。
4. vcvars32 只设 MSVC 的 INCLUDE，需手工补 Windows SDK 路径。
5. 打包器规则：`MAIN` 表 offset 处直接 `TKEY`（无 8 字节表名），其余表先放表名；块按表名字典序、无填充、`MAIN` 首块。
6. `apply_zh.py` 末尾可能报 `OSError: [Errno 22]`，文件已正确写出，可无视。
7. Ghidra 全量分析必炸（Decompiler 堆不足），勿再发起。
8. **`crc` 是「键名」的哈希，不是文本哈希**：同一句英文文本可能对应多个不同键（如 `MAIN` 里三个键都写 `Dukes`，分别是行政区、车名、其它）。因此**同一英文文本在不同键上可以是不同事物，绝不能只按"最高频"机械统一**。判据用 `python C:\Game\_tools\polysemy_audit.py`：**若各键的德/法译文不同，说明原版里就是不同事物，必须按语境分开译**。已因此查到并纠正 9 条误统一（见变更历史）。
9. 覆盖表 `zh_global.tsv` 的 `chapter` 列一律留空（= 全章生效）：同一个 crc 会在 base/TLAD/TBoGT 的多张表里重复出现，按章节过滤会漏改（踩过）。另外重写该文件时**必须先读后写**，历史上一次以 `w` 模式打开导致覆盖表被清空、只能按脚本链路重建。
