# GTA4 简中补完补丁 — 技术原理

> 回答三个问题：**待翻译的内容怎么取得、补丁怎么制作、补丁怎么生效**。
> 配套代码索引在文末；所有结论都经实机或离线校验证实，出处以工程内文档为准。

---

## 一、总体架构：三层 + 一个插件

游戏里玩家看到的每个中文字，都要过三道关：

```
文本层    update\{,TLAD\,TBoGT\}common\text\american.gxt   ← 我们改（词条字典）
字库层    plugins\GTA4.CHS\char_table.dat + 三章 fonts.wtd  ← 我们改（允许字符名单 + 字模图）
渲染层    GTA4.CHS.asi（原汉化补丁，挂钩游戏字体函数）        ← 我们不动
修复层    plugins\mapfix.asi（我们写的独立小插件）           ← 只修暂停地图区名的偏移损坏
```

补丁形态 = **7 个文件覆盖 + 1 个新插件**，不改原汉化补丁任何文件，`_ORIGINAL_*` 提供一键回滚。

## 二、文本载体：GXT 字典

- GTA4 的全部界面/对白文本存在 GXT 二进制字典里。游戏优先读 `update\` 覆盖层（本体/TLAD/TBoGT 各一本 `american.gxt`），所以**改 update 层即可生效、不动原始镜像**。
- GXT 结构：TKEY 块（哈希+组名+偏移）+ STR 块（UTF-16LE 字符串）。组名带 `\0` 填充（如 `CREDIT\0\0`），判定前必须去填充。
- **键名哈希已破解**：条目键 = 经典 GTA Jenkins one-at-a-time 哈希，但**输入取小写**（大写版对 info.zon 74 键 0/74 命中，小写版 74/74）。实现见 `01-逆向草稿\zone_map.js` 的 `gtaHash`。意义：可按英文键名直接算哈希定位条目，不用靠"搜哪条英文长得像"猜。
- 读写器 `01-逆向草稿\gxt_io.js`（parseGxt/buildGxt）：先做**字节级往返验证**（parse→build 与原文件逐字节相等）再允许写入，保证只动字符串不动结构。
- 控制码：`~z~`（说话人）、`~b~`/`~s~`（颜色）、`~n~`（换行）、`~INPUT_*~`（按键图标）、`%s/%d`（占位符）嵌在字符串里，翻译时必须**多重集守恒**（只允许新增 `~n~` 断行）。

## 三、原汉化补丁如何显示中文（为什么有"字库白名单"）

来自 GTA4.CHS 源码（GitHub `ckeleshi/GTA4.CHS`，本地参照 `汉化补丁工程\GTA4.CHS-master\`）+ 实机取证：

1. `GTA4.CHS.asi` 启动时按 14 个字节签名扫描 GTAIV.exe（未加壳，签名 14/14 命中），挂钩 `CFont::PrintChar`、`CFont::ProcessString` 等字体函数。
2. 分发逻辑 `PrintCharDispatch`：`TokenType≠0 或 IsNativeChar(c)` → 走原生单字节字体（ASCII/按钮图标）；否则 → 走中文路径 `PrintCHSChar`。
3. 中文路径查 **`char_table.dat`（渲染硬白名单）**：3,5xx 个升序码点，`GetCharPos` 用二分查找，**返回的格号 == 数组索引**；表外字符渲染成字面 `?`。
4. 字模来自三章 `fonts.wtd` 里的 `font_chs` 贴图：4096² DXT5(BC3) 无 mipmap，格 64×66、64 列×62 行；原字库汉字 = Noto Sans SC Bold 渲染（标点另有来源、比例略小）。
5. 游戏原生 `fonts.dat` 的 `[MAP]` 是**单字节(0–255)映射表**，CJK 码点(≥0x4E00)物理上无法寻址——这就是"没被挂钩的绘制路径一遇中文必乱码"的根源。

**推论（本补丁两条硬约束）**：①译文用字必须全部 ∈ char_table，否则出 `?` → 缺字要么改译法、要么补字库；②char_table 必须严格升序且格号==索引 → **新字不能追加末尾，必须插排序位+搬格+整张重编字模图**。

## 四、如何取得待翻译的内容

1. **全库解析**：gxt_io 解析三章字典（810 组、102,096 条），与真原版英文字典（`备份原版\`）按哈希 join，得到《玩家可见文本数据库.tsv》**102,524 行**（英文原文+当前中文+组+章节）。
2. **状态判定**：按"当前值是否含 CJK"分已汉化/未汉化；键名类、数字符号类（27,322+9,458）判为不可见文本。
3. **队列分流**（审计第三阶段）：A 必须 1,292（多人教程/任务对白漏网/MAIN 指令句）、B 推荐 4,359、C 可选 3,479（网站/Credits）、D 不译 36,861。
4. **漏网三张网**：词频普查（对白行英文 token 计数）→ 整条普查（MAIN 纯英文短标签）→ **零门槛 token 扫描**（`sweep_all_residual.js`：13,155 token×23 列，交叉七张译名表/shield/EXCLUDE/组规则分类）。低频漏译（Sharon 类，仅 1 次出现）只有第三张网能抓到。
5. **专名载体定位**：区名 = `common\data\info.zon` 引用的 74 个 GXT 键；车名 = `vehicles.ide` 模型名/游戏名的 gtaHash；街名/桥名 = MAIN 组整条英文短标签（注意后缀锚定正则会漏"方向词结尾"与"同名多哈希"）。
6. **游戏内网站**（范围外）：`pc\html\` 622 个 .whm = RSC5 头 + zlib 体，可解压出 9,033 句，但回写需处理内嵌纹理与 64K 对齐，另行立项。

## 五、如何制作补丁

### 5.1 文本改写：两种引擎 + 三重闸
- **句内替换引擎**（`build_m2_patch.js` 血统）：整词、区分大小写、长名优先；相邻两个被换词自动接 `･`；只改"已含中文"的句子（不造半中半英）；保护=同源盾（真实客串/店名）、CREDIT 组禁句内替换、lookahead（`Francis(?!国际)`）、parenGuard（`(Lyle)` 双语括号注）、车语境闸（车名只在"辆/台/我的/骑/开…"窗口内替换）。
- **整条哈希覆盖引擎**（`build_m10_gxt.js`/`build_v7.js` 血统）：按 Key/哈希整条替换，安全闸=**仅当当前值===英文原文才覆盖**。与汉化组基底叠加时容忍其标点规范化（去标点后字母数字相等即视为同句）。
- **三重硬闸**（任何写入前）：①控制码多重集相等（`~n~` 唯一例外）②译文用字 ⊆ char_table 3,559（只禁"新增表外字"，原文自带的拉丁重音等豁免）③长度上限（净长 ≤40，超长须备注申请）。
- **全局修订 pass**（GLOBAL_FIX）：批次合入后统一跑译名修订（如 洛佩斯→洛佩兹、自由州→自由城），与批次改动合并同一台账行。
- **基底对齐 pass**（V7f 血统，修订层最后一环）：凡我方早期自拟译名与原汉化补丁（无名汉化组/贴吧版）既定用法冲突者，**一律以汉化组为准**。判据 = 三态取证（英文原版 / 汉化组基底 / 我方成品）——汉化组在其对白、弹窗、散文里一贯用的译法即真值（如 中心区/证交区/中心公园/星汇广场/草地公园/纵身大桥/公屋社区/游乐园）；同时补全汉化组未译而实为玩家可见的地名（进区弹窗/问答弹窗 110 条）。区名一改，`gen_zone_table_v7.js` → 重编 mapfix 必须跟跑。
- **清单对账**（gen_untranslated_v1）：交付《未翻译内容清单》前按当前成品 gxt 实值逐条核对——凡条目已含中文且不再含原文英文词（或 token 已全库消失）即视为已译，不再列入；剔除行留档可查。
- **字段级局部层**（V7g 范式，警车电脑地址）：先在 gxt 里按**键名族**定位真实载体（`PDB_ADDR_0..29` = 警车终端 LCPD 数据库 HANGOUT 地址行，键名族 + 同屏 `PC_*` 界面词互为佐证），再以 hash 限定整条替换、且要求"当前值 === 英文原文"才写（未命中/值不符即报错）；**只动展示字段，绝不碰玩家需键入的字段**（姓名/搜索项保持英文，这是反卡关边界）。核对交付清单时按同一 hash 集反向剔除已译行。
- **改值必回写源表**：任何修订层改过译名后，必须把新值写回对应译名表（本次教训：V7f 只同步了区名表，地名表 9 行仍是旧口径，导致对照表同一地名出现两个译法）。
- **对外发布链（2026-09-20）**：`gen_release_v1.js` 生成发布文件夹（**整目录重建**——README/分享链接/地图对照表等附加文件必须写进生成器，否则重跑即丢）→ `verify_release_v1.js` 校验（**使用说明已改名 `使用说明（必读）.txt`**，校验器按新名读并兼容旧名）→ 上传 GitHub 用 `gh api` 的 Git Data 三段（blobs→tree→commit→ref）：**空仓库先 PUT 一个 README 落初始提交（否则 blobs 409）**、二进制走 base64 blob（CLI 长度限制靠 `--input -` 走 stdin 规避）→ `gh release create v1.0` 出发布页（自动附带源码 zip）。
- **安装/卸载 bat 加固范式（2026-09-20）**
  **防呆一类**：安装前用 `for %%I in ("%PKG%.") do set PKGN=%%~fI`（`~f` 会把 `..` 归一化）与 `!GAME!` 同样归一化后比较——**包被解压进游戏目录本身**时源=目标，copy 只会报"文件无法自身复制"，必须明确拦下并指导用户重解压到独立文件夹。：凡写文件的 bat 必须 ①绝对路径（不依赖 CWD）；②复制前 `attrib -r`；③**失败要回显系统原始报错**（再跑一次不带 `>nul` 的 copy）；④失败计数 + 明确诊断 + 非零退出，**绝不静默"成功"**；⑤括号块内不出现裸引号（未闭合引号会让 cmd 静默中止整段）。沙盒验证法：假游戏目录 + 整包复制 + 注入故障（抽掉一个源文件）跑一遍。
- **改名层（V7k 范式）**：用户拍板推翻既有译名时用"全库字面替换"层最省事——**必须用单条正则 + 交替（长优先）**，否则"交易所"会把新写的"证券交易所"再吃一遍（`/证交所|证交区|交易所/g → 证券交易所`，单次扫描不回头）；区名一改仍要走 `gen_zone_table_v7` → **重编 mapfix** 的既有链条。
- **电视字幕轨（V7i 教训）**：CNT/喜剧俱乐部等电视节目的台词在 GXT 里是 **~z~ 字幕轨**（Rockstar 在五个官方语言里都本地化了同键文本，可判为"设计上应显示"）；但 **PC 版实机（含开启「字幕」）不显示电视字幕** → 这类译文属**休眠数据**：保留零副作用，但**不要**据此开发电视字幕功能（新增渲染/脚本路径，风险等级同地图字体）。判据教训：**"文本存在 + 官方本地化" ≠ "本平台可见"，凡按"应显示"下判断前先要用实机证实或找到调用点**。
- **逐词人名层**（V7h 范式）：中英混排的人名按 token 处置——显式规则（人名表 / 常用搭配）在前，泛化规则在后（英文 token 邻近中文→译；英文名后接空格+中文→接 ･；英文名紧贴中文→直连；中文+空格+英文名→按人名接 ･）。**规则一律带中文语境锚点**，纯英文句与 CREDIT 名单绝不命中；持卡边界：LCPD 需键入的姓名字段（`Gavin "Ambrosia"`/`Fitzgerald` 等）保持英文。缺字（斐）走单字补字轮（M4g）。
- **台账**：每轮输出 `*改动明细.tsv`（tag/组/哈希/旧值/新值/批次），校验器拿它做"每条改动必须来历清楚"的溯源基准。

### 5.2 字库工程（M4 系列，五轮迭代）
1. 缺字检测：新译名逐字对 char_table 求差集（`v6_char_gate.js` 等）。
2. 字形渲染：GDI+（PowerShell 内联 C#）用 **Noto Sans SC Bold 62px**、平移 (-31,-42) 渲染新字；三道闸=尺寸包络（w≤61/h≤60，62px 是 fit_sweep 扫出的不触边最大字号）/墨量非空/无裁切。
3. 名单插入：新码点**插排序位**，其后全部条目格号顺移（`GetCharPos` 二分查找决定了这一点）。
4. 字模图重编：解包 wtd（RSC5）→ 读 BC3 → **整张平面搬格**（格高 66 不是块边长 4 的倍数，逐格改会把边界块编两遍）→ 新字写入空格 → 自实现 BC3/DXT5 编码整张回写 → 表末之后必须全空。
5. 每次从 **pristine 原版字库一次插入全部累计新字**（3,517→3,559，六轮 M4/M4b/c/d/e/f），画质损失不累积；verify 断言搬移格量化差 ≤ 阈值、平坦区坏点 0、解压长度不变。

### 5.3 mapfix.asi（暂停地图区名修复插件）
- **病理**：暂停地图区名标签走 `CFont::ProcessString`，但到达时每个字 = **真码点 −0x20**（字体"内部码=码点−0x20"约定被上游多减一次）→ 按错码点查 char_table → 逐字错位/`?`。procdiag 采集 49,489 条实证，52 个乱码串 +0x20 后 52/52 还原。
- **修法**：hook ProcessString 入口 6 字节（选无 .reloc 重定位条目的首指令，ASLR 免疫；`81 ec 8c 0a 00 00` = sub esp,0xA8C）。DLL 内置 75 条区名真值常量（`zone_table.h` 由脚本从**当前成品 gxt 实值**自动生成，纯 ASCII）；入口读 str，**当且仅当精确等于"某区名每字 −0x20"**时把 str 指针换成 DLL 只读常量再走原函数；其余原样透传。
- **安全性**：不绘制、不写游戏内存、真值永不匹配 −0x20 形态（防递归）、修正串指向永久常量（无生命周期问题）。离线仿真（verify_mapfix.js 复刻 C 匹配逻辑跑实测日志）：乱码串全命中、其它 117 串零误伤。
- **译名联动**：区名/州名译名一旦改动，必须 gen_zone_table → 重编 mapfix（`C:\Users\ghh\mfbuild` ASCII 目录，cl /MT /LD /MACHINE:X86），否则地图端回到乱码。

### 5.4 校验体系
每轮三件套：`verify_*`（内容：结构零改动/差异==台账/白名单/保护项/分章期望）、`verify_*_pack`（包结构：载荷齐备/_ORIGINAL==pristine/bat ASCII+CRLF/说明合规文案逐字）、专项（字库/ mapfix 仿真）。合规红线机器检查：原补丁声明逐字保留（全文，含末句"本组将不对此负任何责任"）、署名、免费、不引入破解、不改 GTA4.CHS.asi。

## 六、补丁如何生效

1. **ASI 加载**：游戏启动时 ASI Loader 按**文件名字母序**加载 `plugins\*.asi`：`GTA4.CHS.asi`(G) 先于 `mapfix.asi`(m)。CHS 在自己 DllMain 内**同步**完成 14 个签名扫描——mapfix 必须等它扫完再下钩，故 mapfix 启动时等待 CHS 模块就绪 + 延时 3 秒。
2. **文本生效**：我们的三本 gxt 覆盖 `update\` 层，游戏读字典即得新译文；通讯录排序按原始英文键，改译名不打乱顺序。
3. **字形生效**：char_table.dat 扩容后，新字在挂钩字体路径可查；fonts.wtd 新字模随贴图加载。ASCII 仍走原生字体（原版职责）。
4. **地图生效**：mapfix 在 ProcessString 入口拦截 −0x20 损坏串换真值 → CHS 的中文路径按真码点查表 → 暂停地图/进区弹窗/HUD 区名全部正确。
5. **安装/卸载**：`安装.bat` **三级自动定位游戏目录**（①补丁文件夹相对位置探测 ②Rockstar 注册表 InstallFolder ③Steam 注册表 SteamPath + `libraryfolders.vdf` 库列表；所有候选必须实际存在 `GTAIV.exe` 才采纳），不要求把包放进游戏目录；**先检测原汉化补丁**——判据 = 游戏目录 `plugins\GTA4.CHS.asi`（原补丁实际安装位置，其 release 布局即 `plugins\` 子目录）存在性，兼容根目录兜底；**绝不引用工程内的 GTA4.CHS-master 源码参照目录**（v1.0 首版曾只查根目录导致误报"未检测到"，已修正——路径判据必须对照原补丁 release 实物，不能猜）；未装则给出原补丁 GitHub 链接（https://github.com/ckeleshi/GTA4.CHS ，官网 https://b9348.pages.dev/ ）并中止；覆盖前把现文件备份为 `_ORIGINAL_*`（已存在则不覆盖，保住 pristine 基底）。`卸载.bat` 用 `_ORIGINAL_*` 还原 7 文件并删除 mapfix.asi。v1.0 发布包的两个 bat 为 **GBK 编码全中文提示**（首行 `chcp 936`，经 iconv 转码+往返校验生成）。
6. **与其它 mod 共存**：不修改 GTA4.CHS.asi；与 FusionFix 并存已实机验证。

## 七、工具链与环境（复刻须知）

- 脚本全 Node v24（内置 full ICU；无 Python、出网断）；二进制一律写脚本读（.dat/.wtd/.asi）。
- 编译：VS2022 Community cl.exe（x86 目标）；**中文路径下 cl 编不动 → 复制到 ASCII 目录 `C:\Users\ghh\mfbuild` 编译再取回**；.cpp 注释必须纯 ASCII（UTF-8 中文被 MSVC 按 GBK 解码会吞行）。
- bat 规范：工程内部脚本生成的 bat 为 CRLF+纯 ASCII；**v1.0 发布包 bat 例外=GBK 编码中文提示**（首行 `chcp 936`，Node 写 UTF-8 后经 iconv 转 GBK 并做往返校验；UTF-8 bat 在中文 cmd 下必乱码，不可用）；`if` 门控下 `&` 链整段跳过的行为已实测（守卫行安全）；构建成功判据="产物比源码新 + 显式 CL_OK"，别信管道退出码。
- 文本编码约定：TSV/TXT 带 UTF-8 BOM，.md 不带。
- 基底纪律：任何"从基底重建"的脚本，基底只认 `03-补丁构建\备份原版\`（真原版 gxt + pristine 字库），绝不用游戏目录现状。
